# 校准与辨识

[返回说明](README.md)

使用同一版 Rust 上位机和固件 1.6。打开「校准与辨识」，连接 1 Mbit/s 经典 CAN，填写节点号，点「读取节点」。电机固定、空载。齿槽试验在正反方向各需要大约四圈电机轴行程，大约 180° 输出轴。确认行程后再开始。每一步通过后点「保存并回读」，看到设备回读一致再做下一项。

界面图见 [上位机说明](../host-rs/README.md#校准与辨识)。

1. **编码器校准。** 正反转测极对数、编码器方向、电角度偏置，双编码器同时测游标零偏。
2. **电机 R/L 辨识。** 得到这台驱动上的相电阻和 d/q 轴电感。只查看候选值时，设备仍用原来的参数。保存 R/L 会清掉电流 PI、速度 PI、位置环的整定标记，并关掉原来的齿槽表，接着做第 3、4 步。
3. **自动 PID 整定。** 电流环用刚测到的 R/L 计算 PI。YH_JM 在 180、260、350、425 Hz 里选择。保存后写入本次增益，并关掉原来的齿槽表。
4. **齿槽转矩补偿。** 正反匀速扫描后生成 256 点表，复测通过才能保存。这一项可以单独关掉。
5. **导出参数。** 存成 JSON，包含电角度、机械零点、R/L、各环增益和已启用的齿槽表。

需要机械零位时，编码器校准完成后把输出轴放到基准位置，在「电机 → 管理」点「设零点」。

试验中按 **Esc** 或点「停止」。固件在试验里检查相电流、母线、编码器和行程；大约 400 ms 没有收到会话状态请求时关桥。烧录时默认保留参数页。勾选覆盖参数区会清掉这些记录。

命令行在 `host-rs` 目录执行，把接口和节点换成自己的：

```powershell
.\target\release\yfoc-host.exe --interface pcan --channel PCAN_USBBUS1 --id 1 --commission export --commission-output jm1-node1.json
```

运动步骤要加 `--commission-arm`。确认要写入设备时再加 `--commission-save`。子命令有 `inspect`、`encoder`、`rl`、`pid`、`cog`、`export`。

## 试验帧

设备信息的能力 bit7 表示支持这组试验。请求发到 `0x200 + 节点号`，应答在 `0x480 + 节点号`，8 字节，小端。前两字节是操作码和序号。出错时应答操作码的 bit7 置位，第三字节是原因。

| 操作码 | 作用 |
| --- | --- |
| `0x30` | 设备信息 |
| `0x31` | 开始试验 |
| `0x32` | 状态与心跳 |
| `0x33` | 读取样本 |
| `0x34` | 停止 |
| `0x35` | 读暂存参数 |
| `0x36` | 写暂存参数 |
| `0x37` | 初始化暂存，或按完整 CRC 提交 |

字段以固件和 `host-rs` 的实现为准。原生协议里旧的 `0x05` 校准命令从固件 1.5 起返回无效命令，校准走上面这组帧。
