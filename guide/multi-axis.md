# 多轴同步位置控制

[返回说明](README.md)

固件 1.6 和 Rust 上位机 0.3.0 可以在一条 1 Mbit/s 经典 CAN 上同步 1～16 个节点。每个节点一个 ID。目标是输出轴绝对位置，单位 rad。界面图见 [上位机说明](../host-rs/README.md#多轴同步)。

主机每 5 ms 发一帧公共同步，每个参与轴每拍回一帧位置和速度。16 轴大约 3400 帧/s，总线上还有填充位和其它设备时，实际负载会更高。

## 使用

1. 各轴使用不同的节点号（1～63），烧录 `firmware/build/gd32f303/YHorizon-JM.bin`。先完成编码器校准，使用电流内环，并确认位置环、速度环增益已经写入。
2. 打开「多轴同步」，连接 CAN，扫描节点，为每个参与轴加一行。用「用当前位置填入」建立起点，再改绝对目标。重新上电后按这次读到的位置来规划。游标上电取最接近已存零点的等价角度，理论不重复区间为 31 圈电机轴，即输出轴总计 3.875 圈。掉电前的累计角度可能超出该区间。
3. 每段时长 0.2～60 s。可以预装第二段，两段共用时长，段与段之间参考速度回到 0。若某轴的速度或加速度限制更紧，上位机会加长公共时长，并取整到 5 ms。每段位移，以及每个端点相对起点的距离，上限都是 30 rad。
4. 点「开始同步运动」。上位机先停掉手动循环并广播关桥，再逐轴预装，等到全部就绪后一起启动。到位或停止后关桥。需要停住后还保持力矩时，不要依赖结束时的关桥。Esc 停止全部轴。
5. 在「同步反馈」里点节点，看参考位置和实测位置。

命令行示例里的目标是占位，运行前改成台架上的实际角度。CSV 用新文件名，避免盖掉上一份记录。

```powershell
.\target\release\yfoc-host.exe --interface pcan --channel PCAN_USBBUS1 --sync-axis "1=0.15/0.10" --sync-axis "7=-0.25/-0.20" --sync-seconds 1 --sync-arm --sync-log group.csv
```

自己的程序用 [SDK](../sdk/README.md) 的 `run_group`。固件 1.6 在启动前装入整段目标，运行中不逐拍改写各轴目标。

## 保护和到位

准备超时、有轴没就绪或反馈中断时，这一组会停。上位机在反馈落后超过 4 拍、主机调度间隔达到 24 ms，或收到故障时，发送组停止。正在跑的驱动大约 30 ms 没有收到有效同步就关桥。准备状态 2 s 超时。跟踪偏差超过 0.5 rad 时本轴停止。

到位判定：全部轴连续 10 拍同时满足位置偏差 ≤ 0.015 rad、速度 ≤ 0.10 rad/s。最多再等 2 s。

## 帧格式

标准帧，11 位 ID，8 字节，小端。

管理请求发到 `0x200 + 节点`：操作码 u8、序号 u8、会话号 u16、参数 4 字节。回复在 `0x500 + 节点`：操作码、序号、结果、协议版本 1。结果 0 成功，1 参数无效，2 忙，3 驱动未就绪，4 轨迹超限。

| 操作码 | 作用 |
| --- | --- |
| `0x40` CAPS | 询问是否可加入。成功表示空闲、已校准、位置有效。回复末尾是输出轴位置，i32，单位 mrad |
| `0x44` LIMITS | 回复速度上限和加速度上限 |
| `0x41` TARGET | 预装第一段绝对目标，i32 mrad |
| `0x43` SECOND | 可选的第二段，格式与第一段相同 |
| `0x42` ARM | 每段时长（单位 5 ms）、反馈时隙 0～15、是否有第二段。回复里带反馈起点 |

公共同步是标准帧 `0x080`：操作、保留、会话号、周期号。操作 1 为 START，2 为 BEAT，3 为 STOP。会话号非 0。

每轴反馈是 `0x540 + 节点`：会话号、周期号、相对起点的位置（i16 mrad）、速度（i16 mrad/s）。位置和速度都是输出轴。

## 单台记录

下面是一台 YH_JM、PCAN、1 Mbit/s 上的记录，用来说明这组帧在单台上是闭合的：

- 两段各 1 s、位移 0.040 rad：收到 410/410 拍，峰值跟踪误差 0.00491 rad
- 两段各 8 s、位移 0.080 rad：收到 3210/3210 拍，反馈平均 200 Hz
- 图形界面一次短行程：收到 210/210 拍

16 轴的组帧顺序在虚拟总线上核对过。多台电机同时运行时的相位差，以你自己总线上的同步反馈为准。
